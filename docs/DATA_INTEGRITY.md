# 数据一致性与归档规则

## 患者归档

“删除患者”统一改为管理员归档。归档会在同一事务中：

1. 将 `Patient.status` 改为 `archived`，保存操作者、时间和原因。
2. 将未失效处方改为 `archived`。
3. 取消待到诊、已改约或待排期预约，历史已完成、已取消和未到诊记录继续保留。
4. 关闭未完成随访，撤销所有 active 设备会话。
5. 更新兼容 StateDocument 投影并写入包含影响数量的 `AuditLog`。

存在训前评估、待设备、训练中、暂停、待训后评估或待签名场次时，归档返回 `409`。恢复患者只恢复主档，旧处方、旧预约、旧登录会话不会恢复。

## 入口约束

- 新建预约：患者必须 active；处方必须属于该患者、状态为 completed 且有医生签名时间。
- 到诊与设备交接：再次执行相同校验，不能依赖前端按钮状态。
- 患者登录：会话 revoked 或患者 archived 时返回 `410`。
- 预约候选：先查询有效患者，再关联其有效处方，禁止仅从历史处方反推患者。
- 状态投影写入：已有文档必须携带当前 `expectedVersion`。无版本号的旧页面或版本落后的浏览器返回 `409`，不能用缓存快照覆盖数据库。

## 自动检查

`npm run data:check` 检查重复患者号、重复登录号、重复有效设备会话、孤儿关系、跨患者处方、无效预约、场次关系、指标任务归属、报告关系，以及归档患者残留的有效业务。发现错误时以非零状态退出。

当前角色字段用于脱敏调研 Demo。真实部署必须由服务端会话或 JWT/SSO 提供角色，不得信任请求体中的角色字符串。
