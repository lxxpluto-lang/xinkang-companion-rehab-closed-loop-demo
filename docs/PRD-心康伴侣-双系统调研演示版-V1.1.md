# 心康伴侣——双系统医生需求调研演示版 PRD V1.1

## 0. 文档控制与 30 秒摘要

### 0.1 30 秒摘要

心康伴侣不是一个把所有角色塞进同一后台的系统，而是由两个边界清晰、数据互通的使用端组成：

1. **医生 Web 端**：服务于康复医生，负责查看患者与训练数据、制定和确认运动处方、复核异常、审核 AI 报告。
2. **患者训练端**：基于一期 Android 横屏 App 升级，优先适配 iPad/平板横屏，服务于患者和现场治疗师，负责训练准备、设备连接、训练执行、RPE/主诉记录和简化训练结果。

两个使用端共享同一名 Demo 患者、同一处方版本和同一训练会话，但权限、页面和操作严格分离。

本版本用于医生需求调研，不接真实患者、HIS/EMR、数据库或真实设备，不作为临床诊疗工具。

### 0.2 本版本重点解决的问题

| 问题 | V1.1 处理方式 |
|---|---|
| 医生、护士、患者功能混在同一侧边栏 | 拆分医生 Web 与患者训练端两个独立入口 |
| 医生端出现设备启动、暂停等患者操作 | 医生端只读查看当前训练，现场控制移入患者训练端 |
| 患者训练页面信息过密、像医生监护台 | 患者端每屏保留一个主要任务，突出时间、阶段、心率、功率和感受 |
| 页面前后流程矛盾 | 统一为“医生确认处方 → 现场准备 → 患者训练 → 异常/结束 → 医生审核” |
| iPad 尺寸不适配 | 患者端以 1024×768 横屏为主要设计与验收尺寸 |
| AI 权限不清楚 | AI 只生成医生端草稿，患者端不显示 AI 草稿 |

## 1. 产品背景与定位

### 1.1 产品名称

**心康伴侣——冠心病Ⅱ期院内康复多模态 AI 辅助平台**

### 1.2 核心定位

产品定位为：

> 通用设备接入底座 + 多模态训练记录 + 临床闭环 + 医生可控的 AI 辅助。

本产品不是单一功率车控制软件，也不试图在 Demo 阶段替代医院已有的完整 HIS/EMR 或康复管理系统。

### 1.3 Demo 目标

本次医生需求调研 Demo 需要验证：

- 医生是否认可双系统职责划分；
- 医生是否需要集中查看院内患者训练状态；
- 运动处方页面需要哪些评估依据与可编辑字段；
- 训练前核验应由谁完成、哪些项目可以阻断训练；
- 患者训练端应展示哪些指标，哪些指标过于专业；
- 异常时患者、治疗师和医生分别需要看到什么；
- AI 处方建议和报告草稿是否能减少医生整理工作；
- 八段锦/柔韧性等非功率车训练是否值得进入统一报告。

### 1.4 产品原则

1. 医生负责临床决策，患者训练端负责训练执行。
2. 处方、异常复核和报告发布不能由 AI 或管理员代替医生。
3. 患者端只展示患者能理解并能采取行动的信息。
4. 训练控制结果必须区分“请求已发送”和“设备已执行”。
5. 缺失、延迟、断连和模拟数据必须明确标记。
6. Demo 规则必须标注“演示规则，非临床阈值”。

## 3. 角色、系统与权限边界

### 3.1 两个系统

| 系统 | 主要用户 | 核心任务 | 主要设备 |
|---|---|---|---|
| 医生 Web 端 | 康复医生 | 查看、开方、复核、审核、发布 | 桌面 Chrome/Edge、投影 |
| 患者训练端 | 患者、现场治疗师 | 准备、训练、反馈、呼叫、结束确认 | iPad/Android 横屏平板 |

### 3.2 角色权限矩阵

| 功能 | 医生 | 现场治疗师 | 患者 |
|---|---:|---:|---:|
| 查看全部 Demo 患者 | 是 | 仅今日任务 | 仅当前本人 |
| 查看评估摘要 | 是 | 只读必要摘要 | 否 |
| 创建/修改/确认处方 | 是 | 否 | 否 |
| 查看已确认处方 | 是 | 是 | 简化目标 |
| 完成训练前核验 | 查看/必要时确认 | 是 | 回答主诉 |
| 连接设备 | 查看状态 | 是 | 否 |
| 启动/停止设备 | 否，仅查看结果 | 是 | 否 |
| 暂停训练 | 查看 | 是 | 可请求暂停 |
| 呼叫医护 | 查看事件 | 接收并处置 | 是 |
| 记录 RPE/主诉 | 查看 | 可协助记录 | 是 |
| 异常处置 | 复核并决定 | 现场执行和记录 | 上报不适 |
| 审核/发布报告 | 是 | 否 | 否 |
| 查看简化结果 | 是 | 是 | 是 |

### 3.3 关键边界说明

- 医生 Web 端不提供当前训练设备的启动、暂停和停止按钮；
- 患者训练端不提供处方编辑、异常复核和报告发布；
- 为避免新增第三套系统，现场治疗师功能嵌入患者训练端，并明确标注“现场人员区”；
- 后续如果医院明确要求护士独立工作台，再新增护士端，不在本 Demo 中提前假设。

## 4. 端到端业务流程

### 4.1 标准训练流程 `FLOW-TRAINING-01`

1. 医生在 Web 端查看 Demo 患者评估摘要。
2. 医生查看或修改运动处方。
3. AI 可以提供处方建议草稿和依据，但不能生效。
4. 医生确认处方，生成不可覆盖的处方版本。
5. 现场治疗师在患者训练端核对患者、处方、生命体征、主诉和设备。
6. 核验通过后，现场治疗师确认开始训练。
7. 患者训练端展示阶段、时间、心率、功率、踏频和感受入口。
8. 患者按提示提交 RPE 或主诉。
9. 正常结束后生成结构化训练小结。
10. 医生 Web 端展示 AI/模板报告草稿。
11. 医生填写审核意见，修改后发布报告版本。

### 4.2 异常流程 `FLOW-ALERT-01`

1. 异常来源可以是患者主诉、模拟指标、设备断连或演示按钮。
2. 患者端立即提示“停止运动、保持坐姿、等待医护”。
3. 系统记录停止请求已发送，但不得直接显示设备已停止。
4. 现场治疗师到场，确认患者状态和设备状态。
5. 现场治疗师记录现场处置。
6. 医生在 Web 端查看异常证据、停止结果和现场处置。
7. 医生决定终止训练或允许后续恢复。
8. 即使医生允许恢复，也必须由现场治疗师在患者训练端重新执行，系统不得自动启动。

### 4.3 两端数据关系

```text
医生确认处方 V1.0
        ↓
患者训练端加载 V1.0
        ↓
TrainingSession 绑定 V1.0
        ↓
指标 / RPE / 主诉 / 异常 / 处置
        ↓
结构化训练小结
        ↓
医生 Web 端 AI 草稿与医生审核
        ↓
报告版本 V1.0
```

## 6. 医生 Web 端功能说明

### 6.1 医生工作台 `VIEW-DOCTOR-DASHBOARD`

#### 页面目标

让医生进入系统后优先看到需要人工判断的事项，而不是先浏览所有患者。

#### 核心功能点

| 区域 | 展示内容 | 医生操作 | 功能价值 |
|---|---|---|---|
| 今日数据卡 | 今日训练、在训、异常待复核、待审核报告、质量提醒 | 点击进入对应模块 | 快速掌握工作量 |
| 异常待办 | 患者编号、异常类型、触发时间、停止状态 | 进入异常复核 | 高风险任务置顶 |
| 今日流程状态 | 处方、核验、设备、异常和报告节点 | 查看状态 | 判断流程卡在哪里 |
| 今日训练列表 | 患者、风险、处方版本、训练状态、报告状态 | 查看患者、训练或报告 | 从患者维度进入任务 |

#### 规则

- 异常待办优先于普通训练列表；
- 停止失败/超时应置顶；
- 工作台不提供训练控制；
- 所有患者只显示 Demo 编号，不显示真实姓名。

### 6.2 患者与处方 `VIEW-DOCTOR-PATIENT`

#### 页面目标

让医生在同一页面查看必要评估信息、当前处方和 AI 处方建议，并形成医生确认版本。

#### 患者摘要功能点

| 功能点 | 内容 |
|---|---|
| Demo 患者信息 | 编号、年龄、性别、诊断摘要和风险等级 |
| CPET 摘要 | 峰值 VO₂ 等模拟摘要 |
| 6MWT 摘要 | 距离等模拟摘要 |
| 当前处方版本 | 显示当前被训练引用的版本 |

#### 处方功能点

| 功能点 | 内容 |
|---|---|
| 训练方式 | 功率车有氧训练 |
| 阶段 | 热身、主训练、放松 |
| 时长 | 每阶段分钟数 |
| 靶心率 | 模拟值，并标注非临床阈值 |
| 功率范围 | 模拟值 |
| RPE 目标 | 例如 11–13 |
| 注意事项 | 患者不适和现场安全提示 |
| 处方版本 | V1.0、V1.1 等 |

#### AI 建议功能点

| 功能点 | 说明 |
|---|---|
| AI 建议草稿 | 使用“建议医生考虑”，不得写成已生效医嘱 |
| 依据引用 | 最近完成度、RPE、心率达标时间等 |
| 缺失字段 | 例如训练结束血压、主诉缓解时间 |
| 医生修改 | 医生可以修改参数 |
| 医生确认 | 确认后成为下一次训练的可执行版本 |
| 版本保护 | 已确认版本不可覆盖，修改生成新版本 |

#### 关键动作

`ACT-PRESCRIPTION-EDIT`

- 允许角色：医生；
- 结果：页面进入编辑状态；
- 不影响正在执行的训练；
- 修改只有再次确认后才生成新版本。

`ACT-PRESCRIPTION-CONFIRM`

- 允许角色：医生；
- 守卫：处方必要字段完整；
- 结果：生成不可覆盖版本；
- 患者训练端只加载已确认版本；
- 需记录确认医生和时间。

### 6.3 院内训练概览 `VIEW-DOCTOR-MONITOR`

#### 页面目标

让医生了解当前有哪些患者训练、训练到什么阶段、数据是否可信，但不代替现场治疗师控制设备。

#### 功能点

| 功能点 | 说明 |
|---|---|
| 在训任务数 | 当前运行中的训练会话 |
| 设备在线数 | 已连接功率车/传感器数量 |
| 视觉训练来源 | 非功率车训练记录数量 |
| 需要关注 | 异常、低置信度、断连或数据缺失 |
| 多患者列表 | 患者、位置、阶段、HR、目标、训练量和质量 |
| 数据质量标签 | valid、simulated、delayed、missing、disconnected |
| 查看详情 | 进入患者、异常或训练记录详情 |

#### 不提供的功能

- 不提供“开始训练”；
- 不提供“暂停训练”；
- 不提供“停止设备”；
- 不提供患者 RPE 输入；
- 不把最近一次血压描述为连续实时血压。

### 6.4 异常复核 `VIEW-DOCTOR-ABNORMAL`

#### 页面目标

让医生看清“发生了什么、系统做了什么、设备是否执行、现场人员如何处置”，并给出最终决定。

#### 功能点

| 区域 | 内容 |
|---|---|
| 异常事件 | 时间、类型、触发源、描述 |
| 指标快照 | HR、SpO₂、POWER、RPE 等 |
| 停止指令 | 已发送、成功、失败、超时 |
| 物理急停提示 | 失败/超时时置顶显示 |
| 现场处置记录 | 治疗师填写现场事实 |
| 医生复核意见 | 医生填写判断和后续安排 |
| 医生决定 | 终止训练或允许恢复 |

#### 安全规则

- 报警和设备停止是两个不同结果；
- 停止请求已发送不等于设备已停止；
- 停止失败或超时必须提示物理急停；
- 医生复核意见未填写时不能作出决定；
- 未经医生确认不能恢复；
- 医生允许恢复后，也不能由系统自动恢复。

### 6.5 AI 报告审核 `VIEW-DOCTOR-REPORT`

#### 页面目标

减少医生整理数据的时间，但让医生看见所有依据、缺失和不确定性。

#### 功能点

| 区域 | 内容 |
|---|---|
| 事实小结 | 时长、完成度、心率达标、功率、RPE、主诉、异常和完整度 |
| AI 草稿 | 中文医学风格描述，不给诊断结论 |
| 依据引用 | 处方、会话、指标和异常事件 |
| 缺失字段 | 未录入或不可用字段 |
| 数据质量警告 | simulated、delayed、missing 等影响 |
| AI 原文 | 只读 |
| 医生修改文本 | 可编辑 |
| 审核意见 | 发布前必填 |
| 退回修改 | 草稿回到待补充状态 |
| 审核发布 | 二次确认后生成报告版本 |

#### 发布规则

- AI 不能自动发布；
- 医生审核意见未填写时发布按钮不可用；
- 发布前二次确认当前发布人；
- 发布后版本只读；
- 更正必须创建新版本并说明原因。

### 6.6 数据与运营 `VIEW-DOCTOR-OPERATIONS`

#### 页面目标

展示 Demo 的训练规模、异常类型、数据质量和设备/AI 运行情况。

#### 功能点

- 今日训练人次；
- 异常事件分布；
- 数据质量分布；
- AI 草稿生成成功率；
- 模板降级率；
- 设备连接成功率；
- 多模态来源数量；
- Demo 环境复位。

#### 边界

- 指标为 Demo 观察指标，不是正式医院 KPI；
- 复位只恢复本地 Mock 状态；
- 复位不影响任何真实患者或真实系统。

### 7.2 今日训练 `VIEW-PATIENT-TASK`

#### 页面目标

### 7.3 训练准备 `VIEW-PATIENT-PREPARE`

#### 页面目标

让现场治疗师用一个页面完成最小安全确认，并让患者回答当前主诉。

#### 现场人员区

| 功能点 | 内容 |
|---|---|
| 患者身份 | 腕带与任务是否一致 |
| 处方版本 | 是否为医生已确认版本 |
| 功率车设备 | 设备编号和连接状态 |
| 最近血压 | 数值和测量时间 |
| 静息心率 | 当前记录 |

#### 患者状态区

- 胸痛/胸闷；
- 明显气促；
- 心悸；
- 头晕；
- 发热或感染；
- 用药明显变化。

#### 开始训练规则

- 默认未完成现场治疗师确认；
- 未确认时“开始训练”不可用；
- 有阻断项时不能开始；
- 患者、处方或设备发生变化后，原核验失效；
- 现场治疗师确认后才可进入训练页。

### 7.4 功率车训练 `VIEW-PATIENT-TRAINING`

#### 页面目标

让患者在训练中只关注当前阶段、时间、心率、简单节奏和不适反馈。

#### 患者主要信息

| 功能点 | 展示方式 |
|---|---|
| 当前阶段 | 准备/热身/主训练/放松/完成 |
| 训练时间 | 大号计时 |
| 阶段进度 | 简单进度条 |
| 当前心率 | 大号数字 + 目标区间 |
| 功率 | 大号数字 |
| 踏频 | 大号数字 |
| 设备状态 | 已连接/断连 |
| 当前感受 | 最近一次 RPE 和主诉 |

#### 患者操作

| 操作 | 结果 |
|---|---|
| 暂停训练 | 提交暂停请求，并显示暂停状态 |
| 记录训练感受 | 打开 RPE/主诉选择 |
| 呼叫医护 | 训练暂停并显示医护已收到提示 |

#### 现场治疗师操作

- 确认开始；
- 设备连接/重连；
- 到场确认异常；
- 训练结束确认；
- 必要时按现场流程执行物理急停。

#### Demo 工具

原型保留“模拟不适”和“模拟结束”按钮，仅供调研主持人演示。正式患者页面不显示该区域。

### 7.5 RPE 与主诉 `VIEW-PATIENT-FEEDBACK`

#### 功能点

- 感觉良好；
- 有点累；
- 胸闷；
- 头晕；
- RPE 6–20；
- 保存记录时间；
- 记录与当前 TrainingSession 关联。

#### 规则

- RPE 是人工输入，不伪装为连续设备指标；
- 胸闷、头晕等主诉应触发现场关注流程；
- 患者只负责报告感受，不负责判断是否继续训练。

### 7.6 患者异常提示 `VIEW-PATIENT-ALERT`

#### 页面目标

异常时不展示复杂医学原因，只告诉患者立即应该做什么。

#### 患者可见文案

1. 请停止运动，保持坐姿。
2. 医护人员已收到提示并正在处理。
3. 请不要自行恢复训练。
4. 如果设备仍在转动，请停止踩踏并等待医护。

#### 规则

- 异常提示覆盖训练主要区域；
- 暂停其他普通操作；
- 患者不能关闭提示后自行继续；
- 只有“现场治疗师已到场”可以进入后续处置状态；
- 医生复核在 Web 端完成。

### 7.7 训练结果 `VIEW-PATIENT-RESULT`

#### 页面目标

给患者提供简单、不过度医学化的训练反馈，并说明接下来做什么。

#### 功能点

- 训练记录已保存；
- 有效训练时长；
- 完成度；
- 最后一次 RPE/感受；
- 继续坐位休息；
- 等待治疗师复测；
- 医生将在 Web 端审核；
- 下一次仍以医生确认处方为准。

#### 不展示

- AI 报告原文；
- 异常医学解释；
- 医生尚未确认的处方建议；
- 可能引起误解的诊断性结论。

## 8. 状态、规则和数据合同

### 8.1 处方状态

```text
AI 草稿 → 医生编辑 → 医生确认 → 已确认版本
                           ↓
                     下一次训练引用
```

- AI 草稿不能被训练端直接加载；
- 已确认版本不可覆盖；
- 训练中修改只影响下一次训练；
- 历史 TrainingSession 始终保留原处方版本。

### 8.2 训练状态

```text
ready → running → paused → running
                  ↓
               stopping → stopped
                  ↓
              completed
```

- `ready`：核验和设备准备完成前不能进入 `running`；
- `stopping`：停止请求已发送，等待设备回执；
- `stopped`：设备停止或现场急停已确认；
- 异常后不得自动从 `stopped` 进入 `running`。

### 8.3 报告状态

```text
未生成 → AI/模板草稿 → 待审核 → 已退回
                         ↓
                       已审核 → 已发布版本
```

### 8.4 数据质量状态

| 状态 | 含义 | 页面行为 |
|---|---|---|
| valid | 来源有效 | 正常展示 |
| simulated | Demo 模拟值 | 显示模拟标签 |
| manual | 人工补录 | 显示人工来源 |
| delayed | 数据延迟 | 显示最后更新时间 |
| missing | 数据缺失 | 显示缺失，不填 0 |
| disconnected | 来源断连 | 冻结最后可信值，不继续变化 |

### 8.5 核心数据实体

| 实体 | 关键字段 |
|---|---|
| DemoPatient | patient_demo_id、age、gender、risk_level、assessment |
| Prescription | prescription_id、version、status、phases、target_hr、power、rpe |
| TrainingSession | session_id、patient_demo_id、prescription_version、status、data_completeness |
| MetricRecord | metric_code、value、unit、quality_status、measured_at、received_at |
| AbnormalEvent | event_id、type、source、snapshot、command_status、review_status |
| AIReport | report_id、version、content、evidence、missing_information、status |
| VisualTrainingRecord | activity_type、duration、rep_count、confidence、manual_confirmation |

## 9. AI、多模态和临床安全边界

### 9.1 AI 可以做

- 整理评估、处方和历史训练数据；
- 生成处方建议草稿；
- 汇总训练事实；
- 生成异常解释草稿；
- 生成单次/阶段报告草稿；
- 标记证据、缺失字段和不确定性。

### 9.2 AI 不可以做

- 自动诊断；
- 自动确定患者能否训练；
- 自动确认或发布处方；
- 自动控制功率车；
- 自动决定异常后恢复；
- 自动发布报告；
- 在证据缺失时补写确定性医学结论。

### 9.3 多模态功能

多模态训练在本版本主要验证“第二数据源能否进入统一会话和报告”。

功能点包括：

- 八段锦/柔韧性训练类型；
- 训练时长；
- 完成次数；
- 识别置信度；
- 数据来源；
- 低置信度人工确认；
- 默认不保存原始视频；
- 摄像头不可用时支持人工计时/计次的降级思路。

## 10. 验收标准

### AC-01 双系统分离

**Given** 用户进入 Demo  
**When** 查看系统入口  
**Then** 必须明确看到医生 Web 和患者训练端两个入口，两个系统导航和功能不混用。

### AC-02 医生端无患者设备控制

**Given** 医生进入院内训练概览  
**When** 查看在训患者  
**Then** 只能查看摘要和详情，不出现启动、暂停或停止患者设备的按钮。

### AC-03 未确认处方不能执行

**Given** AI 已生成处方建议但医生未确认  
**When** 患者训练端加载训练任务  
**Then** 该建议不能成为可执行处方。

### AC-04 训练准备守卫

**Given** 现场治疗师尚未确认身份、处方、患者状态和设备  
**When** 尝试开始训练  
**Then** 开始按钮不可用，不能创建 running 会话。

### AC-05 iPad 横屏可用

**Given** 浏览器视口为 1024×768 横屏  
**When** 执行患者端完整流程  
**Then** 无横向滚动，关键按钮可见，主要文字和数值清晰，触控目标满足尺寸要求。

### AC-06 患者感受记录

**Given** 患者处于训练中  
**When** 选择主诉并提交 RPE  
**Then** 系统保存主诉、RPE 和时间，并与当前会话关联。

### AC-07 异常患者提示

**Given** 训练中触发模拟异常  
**When** 患者端收到事件  
**Then** 覆盖显示停止运动和等待医护提示，禁止患者自行继续。

### AC-08 停止请求与设备结果分离

**Given** 已发出停止请求  
**When** 尚未收到设备回执  
**Then** 页面只能显示“等待确认”，不能显示“设备已停止”。

### AC-09 异常后禁止自动恢复

**Given** 异常已停止训练  
**When** 设备重新连接或指标恢复  
**Then** 系统保持停止/暂停状态，必须经过医生复核与现场操作。

### AC-10 AI 报告人工审核

**Given** AI 已生成报告草稿  
**When** 医生未填写审核意见  
**Then** 发布按钮不可用。

### AC-11 报告版本

**Given** 报告 V1.0 已发布  
**When** 医生需要更正  
**Then** 创建新版本，V1.0 保持只读可查。

### AC-12 模拟数据标识

**Given** 用户浏览任意 Demo 页面  
**When** 页面展示患者、指标或 AI 内容  
**Then** 必须能看见 Demo/模拟/脱敏标识和临床边界提示。

## 11. 非功能要求

### 11.1 兼容性

- 医生端优先支持 1920×1080 桌面 Chrome/Edge；
- 患者端优先支持 1024×768 横屏；
- 患者端兼容更宽平板和投影；
- 不要求本 Demo 支持手机竖屏。

### 11.2 易用性

- 患者端每屏只有一个主要任务；
- 患者端关键按钮固定在易触达区域；
- 重要状态使用文字、图标和颜色组合；
- 异常提示必须覆盖普通训练信息；
- 医生端异常和报告待办优先于普通列表。

### 11.3 稳定性

- 连续演示期间页面不崩溃；
- 动态指标只在 running 状态更新；
- 断连后冻结最后可信值；
- AI 失败不影响结构化训练记录；
- 页面刷新后应恢复 Mock 初始状态或明确说明状态已重置。

### 11.4 性能

- 页面切换无明显等待；
- 动态指标更新不影响按钮响应；
- 100 条以内 Demo 列表应在 2 秒内展示；
- 不加载真实视频或大型医学影像。

## 13. 医生调研推荐讲解路径

### 13.1 开场：先讲两个系统

建议话术：

> 我们这次不是做一个所有人共用的后台，而是拆成医生 Web 和患者训练平板。医生负责看数据、开处方和审核；患者与现场治疗师负责训练执行。两边共享同一训练会话，但权限严格分开。

需要询问医生：

1. 这种双端划分是否符合实际工作？
2. 现场治疗师和护士是否需要再拆独立工作台？
3. 医生是否需要在 Web 端直接控制设备，还是只需要查看和复核？

### 13.2 医生 Web：讲临床闭环

讲解顺序：

1. 工作台为什么异常优先；
2. 患者评估摘要够不够；
3. 处方需要哪些参数；
4. AI 建议是否有用，证据展示是否可信；
5. 医生是否接受处方版本不可覆盖；
6. 在训概览需要哪些指标；
7. 异常复核需要哪些现场证据；
8. 报告审核能否节省整理时间。

### 13.3 患者端：讲易用性与安全

讲解顺序：

1. 今日训练是否一眼能看懂；
2. 训练准备由谁操作；
3. 患者端显示 HR、功率、踏频是否合适；
4. RPE 和主诉入口是否容易理解；
5. 异常时患者提示是否清楚；
6. 患者是否需要查看更详细结果；
7. iPad 横屏是否符合医院实际设备。

## 15. 版本结论

本版本已经完成以下决策：

- `DEC-SYSTEM-01`：产品拆分为医生 Web 与患者训练端两个系统；
- `DEC-PATIENT-01`：患者端优先适配 1024×768 横屏；
- `DEC-ROLE-01`：现场治疗师操作暂嵌入患者训练端，不新增第三端；
- `DEC-CONTROL-01`：医生 Web 默认只读查看当前训练，不控制设备；
