# 心康伴侣 - 冠心病二期院内康复 AI 辅助平台前端原型 PRD

版本：V1.2 浏览器实测优化版
日期：2026-07-29
适用范围：`心康伴侣-医生调研Demo-v2.1` 前端原型
文档用途：组内汇报、医生调研、前端页面优化与后续开发对齐

## 1. 摘要

心康伴侣面向冠心病 II 期院内康复场景，目标是把“医生处方、患者训练、设备数据、AI 分析、医生审核、处方调整”串成一个可演示、可调研、可扩展的闭环。

本版本不是完整医院信息系统，不连接真实 HIS/EMR、真实数据库或真实设备。它是 3 个月课题验证用的前端 Demo，重点证明：训练数据可以被结构化采集，AI 可以辅助整理和提示，但正式处方、异常复核和报告发布必须由医生确认。

## 3. 产品目标

### 3.1 业务目标

- 支持医院在院内康复场景中演示完整闭环：评估 - 处方 - 训练 - 监测 - 报告 - 审核 - 调方。
- 让医生看到连续训练数据、异常事件和阶段报告，减少整理报告和判断处方调整依据的负担。
- 让患者在训练时清楚知道今日目标、当前阶段、是否安全、何时停止。
- 让课题组用不少于 10 组脱敏案例验证 AI 辅助报告和处方建议的可用性。

### 3.2 前端目标

- 医护 Web 端和患者 Pad 端入口清晰，角色边界明确。
- 医生端以“待处理任务”为核心，而不是做全院大屏。
- 患者端以“一步一任务”为核心，避免把医生监护信息直接塞给患者。
- 所有 AI 输出必须表现为“草稿、建议、提示”，不得表现为自动决策。

## 4. 用户与权限

| 角色 | 核心任务 | 可以做 | 不可以做 |
|---|---|---|---|
| 系统管理员 | 演示权限、资源、签名配置 | 查看全部 Demo 数据、管理视频资源和后台配置 | 不能绕过医生临床确认逻辑 |
| 康复医生 | 处方、报告、异常复核 | 生成/修改/签署处方，审核报告，查看本人患者明细 | 不能在医生端启动/暂停/停止设备 |
| 康复执行岗 | 到诊、设备、现场记录 | 核对身份、连接设备、记录现场处置、上报异常 | 不能签署处方或发布临床报告 |
| 患者 | 完成训练与反馈 | 查看本人今日训练、确认处方、提交感受、完成训练 | 不能修改处方参数或查看 AI 医学草稿 |

## 5. 页面与流程

### 5.1 双系统入口

页面当前有效地说明了两个端：

- 医护 Web 工作站：角色权限登录、医生处方工作台、康复执行与随访、后台配置与审计。
- 患者训练端：今日任务、训练准备、阶段引导、训练结果。

优化要求：

- 保留双入口结构。
- 强化“需求调研 Demo、模拟/脱敏数据”的提示。
- 入口页不承载复杂业务说明，只负责让调研对象快速进入正确角色。

### 5.2 医护 Web 登录

当前页面支持系统管理员、康复医生、康复执行岗三种身份，并展示权限预览。

优化要求：

- Demo 可保留角色卡片快速切换账号。
- PRD 和演示时要明确：正式产品必须使用医院身份认证和服务端权限校验。
- 登录页的权限说明建议改得更贴近医院岗位，例如“康复执行岗”可说明为治疗师/护士现场执行角色。

### 5.3 医生今日工作台

医生首页定位为全局业务概览，不再只统计今日预约。顶部固定展示五项指标：

- 总患者数：168；辅助说明“本月新增 12”。
- 总运动处方量：42；辅助说明“当前执行”。
- 平均训练完成率：83%；辅助说明“本月平均”。
- 训练异常记录数：5；辅助说明“等待处理”。
- 待开具处方数：按所有 `status !== completed` 的处方任务动态计算。

“待开具处方数”是可操作指标。点击后必须进入处方管理页面，状态筛选自动选中“未完成”，列表立即排除已完成处方。工作台不再重复展示完整的未完成处方表，保留趋势、提醒与今日预约患者区域。今日预约患者默认按时间展示 3 条并明确标注预约时间；超过 3 条时通过“查看全部”展开完整名单。

处方管理采用查询表单，不使用预设数量状态卡。筛选项包括患者编码、处方编码、所属医生和状态；状态支持全部、未完成、待生成、待复核、待签名和已完成。查询按钮一次性应用组合条件，重置按钮清空条件并恢复全部处方。患者编码和处方编码支持忽略大小写的部分匹配，所属医生和状态采用精确匹配。

处方任务必须记录明确的所属医生字段，页面不得再根据签署人或默认医生推断。对“信息待补充”的任务继续展示缺失字段提示，避免医生进入审核后才发现不能签署。

### 5.4 处方审核页

当前页面展示：

- 处方版本，如 V5.0 草稿
- 处方内容，包括呼吸、有氧、抗阻、柔韧训练
- 患者临床摘要
- AI 复核建议
- 保存草稿、确认完成并签署

页面逻辑符合“AI 辅助、医生确认”的原则。

优化要求：

- AI 建议旁必须固定显示“辅助信息，不替代医生判断”。
- 确认签署前必须要求医生勾选“已核对评估依据、安全事件和处方内容”。
- 完成签署后，处方版本不可覆盖，只能生成新版本。
- 处方页建议增加“本次调方原因”字段，来源可以是阶段报告、单次异常、首次评估或医生手动录入。

### 5.5 训练工作台

当前医生视图展示：

- 今日计划患者、已到诊患者、在训患者、已完成训练、异常/设备提醒
- 多名患者训练任务
- 设备、训练阶段、心率、进度、状态
- 异常上报闭环

页面已体现医生只读观察边界。

优化要求：

- 医生视图保留只读，不提供设备控制按钮。
- 康复执行岗视图需要突出“到诊确认、设备连接、现场记录、异常上报”。
- 设备异常要独立于患者异常展示，例如蓝牙断连、数据未回传、血压未补录。
- 数据质量要有显式状态：正常、缺失、延迟、人工补录、模拟数据。

### 5.6 患者训练端首页

当前患者首页展示：

- 今日处方：功率车 30 分钟
- 运动方式选择：呼吸、有氧、抗阻、柔韧、中医运动
- 已选择功率车
- 目标心率 100-116 bpm
- 累计完成 11/36 次
- 下次随访时间

页面定位正确：患者先看“今天做什么”。

优化要求：

- 对非功率车训练明确当前状态：已支持视频跟练、仅入口展示、待设备接入。
- “护士操作区”应更明确：哪些是患者自己可点，哪些必须护士确认。
- 对患者展示应减少专业术语，例如“靶心率”可显示为“建议心率范围”。

### 5.7 患者训练流程

当前功率车流程为：

1. 处方确认
2. 设备连接
3. 心理准备
4. 血压模式
5. 开始训练

浏览器实测发现：

- 处方确认页只读展示医生已审核签署处方，逻辑正确。
- 设备连接页要求智能监测背包和功率车都连接通过后才能继续。
- 心理准备页为必答项，未完成 3 项选择不能继续。
- 血压模式包括“测量 2 次、分阶段测量、本次不测量”。

优化要求：

- 训练前门槛写成硬规则：身份未确认、处方未确认、设备未通过、心理/主诉未完成、血压模式未选择时，不允许进入训练。
- “本次不测量”必须显示需医护确认，不应作为患者默认选择。
- 训练页应保留患者能理解的关键指标：阶段、剩余时间、心率、功率/RPE、停止提示。
- 患者端异常提示必须先告诉患者怎么做：停止运动、保持坐姿、等待医护。

## 6. AI 功能边界

AI 在本产品中只承担辅助角色：

- 整理患者评估、训练记录和异常事件。
- 生成处方建议草稿。
- 生成单次报告和阶段报告草稿。
- 标记缺失数据、异常风险和需要医生重点关注的内容。

AI 不允许：

- 自动诊断。
- 自动开具或发布处方。
- 自动签名。
- 自动发布报告。
- 自动启动、暂停、停止或恢复设备。
- 把演示阈值描述成临床标准。

## 7. 数据需求

### 7.1 处方数据

至少包括：

- 患者 ID、处方版本、医生、签署时间
- 训练类型、频次、时长、强度、目标心率、功率/阻力、RPE
- 热身、主训练、放松时间
- 禁忌、注意事项、饮食提醒、停止运动条件
- 调方原因和依据来源

### 7.2 训练数据

至少包括：

- 训练会话 ID、绑定处方版本、训练项目
- 阶段、时长、完成度
- 心率、功率、踏频、速度、距离、血氧、血压测量点、RPE
- 主诉、异常事件、现场处置、医生复核
- 数据来源、数据质量、缺失字段、是否模拟/脱敏

### 7.3 报告数据

至少包括：

- 单次训练报告
- 阶段性报告
- 目标区间达标情况
- 安全事件
- 功能变化
- 患者感受
- 医生反馈和下一阶段建议

## 8. 问题与解决策略

| 浏览器实测/资料发现 | 风险 | 解决策略 |
|---|---|---|
| 医生首页有异常报告数量，但缺少独立异常列表入口 | 医生难以快速处理高风险任务 | 增加异常报告列表或从指标卡跳转到筛选后的异常任务 |
| 今日预约和处方任务关联偏弱 | 医生需要在多个入口之间找上下文 | 预约患者详情中固定展示报告、处方、异常和下一步操作 |
| 患者端训练前步骤较多 | 患者可能不知道当前卡在哪一步 | 保留顶部步骤条，并在每页只放一个主要按钮 |
| 心理准备必答项阻断流程，但提示不够明显 | 未选时用户可能以为按钮坏了 | 未完成时显示“还差 X 项未选择”，并高亮未答问题 |
| 血压“本次不测量”可能被误点 | 影响安全数据完整性 | 选择该项时要求二次确认，并记录确认人 |
| 医生端数据质量表达不够系统化 | 医生可能把模拟/缺失数据当真实完整数据 | 所有报告和训练卡增加数据质量标签 |
| 多训练类型已有入口，但完整流程主要是功率车 | 需求范围容易被误解 | PRD 明确 V1 以功率车闭环为主，其他训练为扩展或视频跟练 |
| 自动化测试中部分按钮定位困难 | 后续测试维护成本高 | 为关键页面和按钮补充稳定 `data-testid` |

## 9. 验收标准

### 9.1 正常闭环

- 医生可登录医护 Web。
- 医生可看到待处理处方任务。
- 医生可生成或打开 AI 处方草稿。
- 医生可编辑、确认、签署处方。
- 患者可登录 Pad 端。
- 患者可按步骤完成处方确认、设备连接、心理准备、血压模式选择和训练。
- 训练完成后可生成训练结果，并进入医生报告审核链路。

### 9.2 异常闭环

- 训练中可触发异常或主诉。
- 患者端先提示停止运动和等待医护。
- 康复执行岗记录现场事实。
- 医生端查看异常证据并复核。
- 异常结论影响下一阶段处方建议。

### 9.3 权限验收

- 医生可审核处方和报告，但不能控制设备。
- 康复执行岗可处理现场任务，但不能签署处方。
- 患者只能查看本人训练和报告。
- 管理员可管理资源和配置，但正式临床结论仍需医生身份确认。

### 9.4 前端验收

- 患者端在 1024 x 768 横屏下核心流程可用。
- 页面文字不遮挡、不溢出主要按钮。
- 每个关键页面有稳定测试标识。
- Demo 数据、模拟设备、AI 建议均有明确标注。
- 医生和管理员工作台显示五项全局指标，待开具处方数与当前未完成处方数据一致。
- 点击待开具处方指标后进入处方管理，状态显示“未完成”，结果中不包含已完成处方。
- 处方管理支持患者编码、处方编码、所属医生、状态的单项及组合查询；未点击查询前列表不变化。
- 点击重置后清空全部筛选条件并恢复完整处方列表。
- 康复执行岗工作台不受本次医生工作台改版影响。

## 10. 本期范围与非范围

### 10.1 本期范围

- 双系统入口。
- 医护角色登录。
- 医生工作台。
- 处方审核和签署。
- 训练工作台。
- 患者训练 Pad 主流程。

- 单次/阶段报告展示。
- AI 草稿和医生审核边界表达。

### 10.2 本期不做

- 不接真实患者数据。
- 不接 HIS/EMR。
- 不接真实数据库。
- 不控制真实设备。
- 不做 AI 自动诊断。
- 不做 AI 自动开方。
- 不做院外居家小程序。
- 不把演示阈值当临床标准。

## 11. 推荐下一步

1. 先用本 PRD 做一次组内对齐，确认是否以 V2.1 作为汇报主原型。
2. 再邀请医生按“医生工作台 - 处方审核 - 训练工作台 - 患者端训练”路径试用。
3. 收集医生对处方字段、异常复核、报告内容和设备接入的反馈。
4. 根据反馈拆成前端优化清单，优先修：异常入口、缺失字段提示、训练前阻断提示、数据质量标签。
