# 冠心病 II 期运动康复闭环数据流

## 阶段划分判断

原图按“训练前评估与处方准备 / 院内训练执行与安全监测 / 报告评估与持续管理”三段划分是合理的，但素材需要删减为数据闭环视角：

- 患者端不应放在“后续扩展”，而是贯穿第二、三阶段的数据入口与反馈出口。
- 第一阶段不要画成“资料堆叠”，核心是体能测试记录、患者档案、风险分层、处方四类数据能互相带出。
- 第二阶段不要重复展示所有临床指标，重点是本次训练执行、实时安全、异常处置、治疗记录。
- 第三阶段不要重复患者基础信息，重点是单次报告、阶段报告、处方调整、患者端随访反馈回流。

## 主数据流

体能测试记录（图片 / PDF / OCR）
→ 患者档案（姓名、风险分层、系统生成患者号、档案号）
→ 体能评估记录（SPPB、血压、脉搏、握力、步速等）
→ 医生处方（运动形式、目标心率、功率、配速坡度、血压反应、停止条件）
→ 预约与到诊
→ 院内训练执行（功率车 / 抗阻 / 拉伸）
→ 训练中监测（心率、血压、RPE、症状、异常）
→ 治疗记录 / 单次训练报告
→ 阶段报告
→ 医生复核与处方调整
→ 患者端查看报告、执行提醒、随访反馈
→ 管理员看板与质量追踪

## 四类角色闭环

| 角色 | 核心动作 | 重点指标 | AI 减负点 |
| --- | --- | --- | --- |
| 患者 | 到诊确认、训练配合、查看报告、提交随访反馈 | 今日训练任务、完成情况、症状反馈、家庭执行状态 | 报告通俗化、运动提醒、随访问答初筛、异常自述结构化 |
| 康复师 | 体能测试录入、到诊核对、训练执行、异常初处置、治疗记录 | 训练完成率、本次心率/RPE/血压、异常次数、记录完整性 | OCR录入、训练记录自动生成、异常摘要、阶段报告草稿 |
| 医生 | 风险分层确认、处方制定/调整、异常医学复核、报告确认 | 风险等级、处方状态、异常趋势、阶段改善、是否需调方 | 处方草稿、既往处方对比、异常分级建议、报告医学摘要 |
| 管理员 | 角色权限、资源排班、质量质控、数据完整性 | 患者总量、预约利用率、记录缺失率、报告发布率、权限日志 | 缺失字段巡检、质控提醒、跨角色任务追踪、统计摘要 |

## 页面指标去重原则

- 患者档案：只放身份、患者号、档案号、风险分层、诊断、责任医生、康复阶段。
- 体能评估：只放评估表本身和评分结果，不重复训练执行指标。
- 处方管理：只放处方版本、来源、状态、医生、运动强度和停止条件。
- 训练执行：只放本次训练计划、实时监测、异常、实际完成情况。
- 报告评估：只放单次/阶段汇总、变化结论、缺失数据、是否触发调方。
- 患者端：只放患者能理解和执行的信息，不展示医护端完整工作量指标。
- 管理员端：只看任务与质量统计，不进入具体临床判断。
