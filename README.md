# 心康伴侣：冠心病运动康复全流程闭环 Demo

> 本目录是独立的下一版原型，不覆盖历史 Demo，可通过本地 Git 回退。

在线预览：[GitHub Pages](https://lxxpluto-lang.github.io/xinkang-companion-rehab-closed-loop-demo/)

本版本以原图文 PRD 为主体，并吸收业务组会议已确认的修正，覆盖：**患者资料、医生处方、预约到诊、训练执行、异常闭环、康复报告与轻量随访**。

系统不替代 HIS/EMR。处方模块仅演示 AI 辅助草稿、医生三值对比复核、签署与发布；没有可靠处方分母时，训练端只统计实际发生次数。

## 核心闭环

`OCR 导入患者资料 → 人工核对 → 医生生成/复核处方 Demo → 预约到诊 → 训练前评估 → 设备连接 → 视频训练 → 异常现场处置/医生复核 → 单次报告 → 康复师一键生成阶段报告 → 发送康复报告/康复手册 → 人工电话随访`

明确不做：

- 对接真实处方系统或开具真实医疗处方
- AI 自动诊断、自动调方、自动签署或自动发布
- 医生在本系统维护完整病历和医嘱
- 患者注册、自助建档或填写随访问卷
- AI 外呼
- 患者签署临床报告

## 医护 Web 端

业务菜单：

- 今日工作台：随访待办、报告概览、今日到诊与训练概览
- 患者档案：基础档案、体能评估、治疗记录、训练与报告、随访记录
- 处方管理：AI辅助草稿、上一版/AI建议/医生最终值对比、医生签署发布
- 异常告警：事件快照、康复师现场处置、医生复核、Demo规则配置
- 预约管理：日历、患者、运动项目、工位、完成/取消与冲突校验
- 随访管理：出院报告发布后生成提醒，支持短信/在线提醒展示、人工电话记录和高风险升级
- 训练大屏：患者到诊、项目核对、训练前评估、设备检查、训练执行、训练后评估与单次报告

体能评估是患者数据详情的子页面，不作为侧边栏一级菜单。

后台仅保留：

- 视频资源
- 组织权限
- 报告打印签名

权限边界：

- 康复师记录训练事实、体能评估、治疗记录、人工随访，并生成及发送阶段/康复报告
- 医生查看团队患者，只能编辑和签署本人处方任务，并复核已提交的异常事件
- 管理员配置账号、权限、视频和签名模板，但不能编辑临床业务或代签
- 患者只能查看本人已发布的内容

## 患者训练 Pad

- 首页保持训练、日历、报告、个人四个一级入口
- 今日运动项目由康复师对照医院正式处方选择
- 右侧显示累计实际训练次数、本月次数、分项目次数、实际时长、报告数量和“我的康复手册”；不展示计划分母或处方完成率
- 功率车训练使用沉浸式视频，悬浮显示运动时间、剩余时间、阶段进度和独立心率区域
- 底部展示速度、距离、功率、阻力、热量、血氧和间歇血压测量点
- RPE 由患者或康复师主动选择，不设置默认值
- 训练完成后可查看单次报告
- 不显示 AI 内部草稿、医生内部意见、处方编辑或患者自填随访入口

## 报告口径

单次报告来自一次实际训练，区分训练前、训练中和训练后指标；血压只展示带时间的间歇测量点，不模拟连续曲线。

阶段报告默认选择上一份已发送报告之后的已完成训练，也可由康复师取消不适合比较的记录。报告保存实际训练记录 ID，按运动类型分别汇总，不计算处方完成率。

出院报告发布后，患者端才能查看康复手册并生成后续随访提醒。网页预览可使用轻量动画，PDF 保持静态、可打印的医疗文书样式。

## 安全声明

- 仅使用本地 Mock、模拟或脱敏数据，不接真实患者和真实设备。
- OCR、HIS、短信、数字签名和设备接口均为交互演示。
- 缺失字段显示“未采集”，不按 0 参与均值或趋势结论。
- 演示阈值不等同于临床标准。
- 本系统不生成诊断结论，不提供自动诊断、自动处方或自动设备控制；需要医疗判断时回到线下临床流程。
